# AFAL Site Market 2.0

Двомовний сайт AFAL із каталогом послуг, тарифами, портфоліо концептів, консультантом, калькулятором і відстеженням заявок. Калькулятор, консультант і сервер використовують однакові тарифи з `public/catalog.mjs`.

## Локальний запуск

Потрібен Node.js 24 або новіший. Проєкт використовує вбудований SQLite і працює без встановлення пакетів.

```sh
node scripts/build.mjs
node --test
node --env-file-if-exists=server/.env server/server.mjs
```

Якщо встановлено npm, ці ж команди доступні як `npm run build`, `npm test` та `npm start`.

Відкрийте <http://127.0.0.1:3000/> або <http://127.0.0.1:3000/en/>. За замовчуванням заявки зберігаються в `.local/orders.sqlite`. Локальні заявки та відстеження працюють без облікових даних Telegram і OpenAI. У такому режимі консультант формує рекомендацію за каталогом, а відповідь сервера позначає сповіщення Telegram як недоступне.

Для локального налаштування скопіюйте `server/.env.example` в `server/.env` та заповніть потрібні змінні. Файл із секретами та файли бази виключені з Git.

## Статичний сайт на GitHub Pages

`node scripts/build.mjs` генерує `index.html`, `en/index.html` і файли для пошукових систем. Збережіть у коміті згенеровані файли й `public/` разом зі змінами в джерелах. У GitHub відкрийте **Settings → Pages**, виберіть **Deploy from a branch**, гілку `main` і папку `/(root)`. За зміни основної адреси задайте `AFAL_SITE_URL` перед збіркою, щоб оновити canonical, мовні альтернативи й sitemap. [Документація GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

Поки серверна адреса порожня, на GitHub Pages працюють каталог, калькулятор і консультант за каталогом. Конструктор готує чернетку в чаті `@artemis393`, яку клієнт надсилає самостійно. Онлайн-відстеження стає доступним після підключення API.

## Окремий сервер API

1. Розгорніть репозиторій на хості, який підтримує постійний процес Node.js 24+, постійний диск і публічний HTTPS. Запускайте `npm start` або команду `node` з інструкції локального запуску. На хостингу зазвичай потрібен `HOST=0.0.0.0`, а `PORT` задає платформа. `AFAL_SERVE_STATIC=false` залишає лише API.
2. Спрямуйте `AFAL_DB_PATH` на файл у приватному каталозі постійного диска, наприклад `/data/afal/orders.sqlite`. Використовуйте один процес API й регулярні резервні копії SQLite. За наявності зворотного проксі задайте `AFAL_TRUST_PROXY_HOPS` лише для відомої кількості довірених проксі.
3. Для адреси `https://afal708.github.io/afal-site-market/` CORS уже налаштований. Для власного домену допишіть його origin у `ALLOWED_ORIGINS`, наприклад `https://www.example.org`. Декілька origin розділіть комами. Origin містить схему і домен без шляху або кінцевої косої риски.
4. У `public/deployment.mjs` задайте `API_BASE` як HTTPS-адресу сервера, наприклад `https://api.example.org`. Це публічне налаштування. Після оновлення перевірте `GET /api/health`, створіть тестову заявку з вигаданими даними та перевірте її статус за виданим кодом.

### Telegram і консультант

| Змінна | Дія |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен від BotFather у секретах сервера. |
| `TELEGRAM_CHAT_ID` | ID приватного чату або групи, до якої додано бота. Для особистого чату одержувач спочатку відкриває бота й натискає Start. |
| `OPENAI_API_KEY` | Серверний ключ, який вмикає доповнення технічного завдання через OpenAI. |
| `OPENAI_MODEL` | Модель, доступна для ключа. За замовчуванням використовується `gpt-4.1-mini`. |
| `AFAL_ADMIN_TOKEN` | Випадковий секрет від 24 символів для адміністрування статусів. |

Сервер спочатку зберігає заявку та код. Після цього він надсилає сповіщення боту. За тимчасової помилки сповіщення має статус `pending` і повторюється автоматично. Запит `GET /api/health` показує наявність налаштувань, а доставку підтверджує `notification: "sent"` у відповіді на заявку або перевірку статусу. [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)

За підключеного `OPENAI_API_KEY` сервер запитує уточнення до технічного завдання. Базовий тариф і конфігурацію завжди обчислює каталог. У разі недоступності OpenAI клієнт отримує результат за каталогом. [OpenAI Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)

### Оновлення статусу

`PATCH /api/admin/orders/<код>` приймає JSON зі статусом і заголовок `Authorization: Bearer <токен>`. Доступні статуси `received`, `in-review`, `in-progress`, `ready`, `completed` і `cancelled`. Щоб повторити надсилання в Telegram, передайте `{"retryTelegram":true}`. Код заявки видно у сповіщенні Telegram та підтвердженні клієнта.

У PowerShell використайте `AFAL_ADMIN_TOKEN` і `AFAL_ORDER_CODE` зі змінних поточного процесу.

```powershell
$api = 'https://api.example.org'
Invoke-RestMethod -Method Patch -Uri "$api/api/admin/orders/$env:AFAL_ORDER_CODE" `
  -Headers @{ Authorization = "Bearer $env:AFAL_ADMIN_TOKEN" } `
  -ContentType 'application/json' -Body '{"status":"in-progress"}'
```

### Дані заявок

Форма збирає ім’я, спосіб зв’язку та опис за згодою клієнта. Вона надсилає їх HTTPS-запитом на сервер, який зберігає дані у SQLite й передає заявку у приватний чат Telegram, якщо бот налаштований. Публічне відстеження повертає статус і дати лише за випадковим кодом. Клієнтська чернетка для Telegram містить вибрані параметри без контактів із форми, а браузер зберігає лише налаштування теми. Консультанту надавайте тільки вимоги до сайту. Сервер маскує типовий формат контактів перед викликом OpenAI.

Зберігайте ключі, базу та резервні копії в приватному сховищі. Оператор сервера керує доступом, строком зберігання та видаленням даних з бази, резервних копій і Telegram.
